# 演習

`claude` を起動した状態で進めてください。
各演習は独立しているので、詰まったら次に進んで構いません。

---

## 演習1 — コードベースを理解させる（5分）

AIに既存コードを説明させる体験です。まずはこう聞いてみてください。

```
このプロジェクトの構成と、タスクが作成されるまでの処理の流れを説明してください。
```

続けて、掘り下げてみましょう。

```
store.js の list() は何をしていますか。引数を省略した場合はどう動きますか。
```

**ポイント**：AIはあなたのリポジトリを実際に読んでいます。
一般論ではなく、このコードに即した答えが返ってくることを確認してください。

---

## 演習2 — 機能を追加させる（10分）

タスクに「優先度」を追加します。

```
タスクに priority フィールドを追加してください。
値は 'low' | 'normal' | 'high' の3種類で、省略時は 'normal' とします。
バリデーションは validate.js の既存パターンに合わせ、
テストも追加した上で npm test が通ることを確認してください。
```

**確認してほしいこと**：

- `AGENTS.md` に書かれた規約（結果オブジェクトを返す、named export）に従っているか
- テストを勝手に緩めていないか
- 変更後に実際に `npm test` を実行して報告してきたか

余力があれば、続けて聞いてみてください。

```
今の変更を、サーバーのAPI（POST /tasks）からも使えるようにしてください。
```

## 演習3 — バグを直させる（10分）

現在 `npm test` は1件失敗します。まず自分で実行して確認してください。

```bash
npm test
```

そのうえで、AIに依頼します。

```
npm test が1件失敗しています。原因を調査して修正してください。
テストの方を書き換えるのではなく、実装側に問題がないか先に検討してください。
```

**ポイント**：これは境界値のバグです。
「テストを消せば緑になる」という誘惑に対して、AIがどう振る舞うかを観察してください。
`AGENTS.md` にそのルールを書いてあることが、挙動にどう効いているかも確認できます。

## 演習4 — 自由課題（残り時間）

思いついたものを投げてみてください。例：

```
このAPIに、タスクの検索エンドポイントを追加してください。
```

```
README を読んで、この構成の弱点を3つ指摘してください。
```

```
テストのカバレッジが薄い箇所を特定して、足りないテストを追加してください。
```

```
src/server.js のルーティングが増えると読みにくくなりそうです。
リファクタリング案を、実装せずにまず提案してください。
```

## 使ってみてほしい操作

| 操作 | 説明 |
|------|------|
| `/help` | コマンド一覧 |
| `/clear` | 会話をリセット（話題を変えるとき） |
| `Esc` | 生成の途中停止 |
| `#` で始める | 学んだ内容を CLAUDE.md に記憶させる |

# 運営ガイド（RST）

このファイルはパブリックリポジトリに含まれます。
**キー・Workspace ID・請求情報などの機密は絶対に書かないでください。**

---

## 1. 設計の前提

### なぜ fork させないのか

公開リポジトリからは、fork せずに直接 Codespace を作成できます。
Codespace の計算コストは**作成した本人の個人アカウント**に課金され、
GitHub Free の個人アカウントには月120コア時間・15GBの無料枠があります。

fork を挟まないことで、受講生の操作が「Create を押す」だけになります。

### なぜ GitHub のシークレット機能でキーを配らないのか

**配れないからです。**

リポジトリレベル／Organizationレベルの Codespaces シークレットは、
作成・管理できるのは admin 権限保持者で、
**使用できるのは collaborator 権限を持つユーザーだけ**です。
公開リポジトリの一般閲覧者は collaborator ではないため、シークレットは注入されません。
fork にも渡りません。

これは仕様の欠陥ではなく意図的な防御です。
もし公開リポジトリのシークレットが「Create した全員」に渡るなら、
世界中の誰でもボタン一つでキーを取得できてしまいます。

`devcontainer.json` の `secrets` プロパティ（recommended secrets）も
**値を配る機能ではありません**。あれは「Codespace を作るユーザー自身が
自分のキーを入力する」ことを促すための宣言的メタデータです。

### 結論としての方針

キーを秘匿して配る方法は存在しないため、
**「読まれても損害が出ない／即座に殺せる」設計**に振ります。

| 守る対象 | 手段 |
|---------|------|
| 露出範囲 | 参加者のみ（口頭・画面・チャットで配布。リポジトリには置かない） |
| 金額 | Workspace のスペンド上限で頭打ち |
| 時間 | 終了後に Workspace をアーカイブして即失効 |

## 2. この構成が採っている防御

環境構築で受講生が詰まる箇所を、あらかじめ潰してあります。

| リスク | 対策 |
|--------|------|
| `remoteUser` 不一致で `$HOME` がずれる | **指定しない**（イメージ既定に従う） |
| マシンスペック確保に失敗 | `hostRequirements` を**指定しない** |
| features のビルド失敗 | **features を使わない** |
| npm install の瞬断 | **3回リトライ**する |
| npm install 失敗でコンテナ生成ごと失敗 | bootstrap は**常に exit 0**。コンテナは必ず生きる |
| PATH が通らない | **3経路**（`~/.local/bin` リンク / rc追記 / `npx`） |
| bash 以外のシェル | `.bashrc` `.zshrc` `.profile` の**3つ全部**に書く |
| モデル名変更で診断が誤検知 | 疎通確認は `/v1/models` を優先（**モデル名に依存しない**） |
| 拡張機能がログインを要求して混乱 | **VS Code 拡張を入れない**（CLI に統一） |

> Claude Code の VS Code 拡張は、既定で Anthropic アカウントへのログインを促します。
> APIキー運用の本セミナーでは「サインインを求められて止まる」事故になるため、
> あえて外してあります。使いたい場合はログインプロンプトの無効化設定を
> 事前検証したうえで追加してください。

## 3. 事前準備

### Anthropic Console 側

1. セミナー専用の **Workspace** を新規作成（例: `seminar-2026-07`）
   - 既存の本番 Workspace は絶対に使わない
2. **スペンド上限**と**レート上限**を設定
   - レート上限は同時アクセスで詰まらない範囲に
3. その Workspace 内で **APIキーを1本発行**
   - 発行時にしか全体が表示されないので、その場で控える

### リポジトリ側

1. RST の Organization 配下に **Public** で作成
2. `README.md` 内のリンクを実際のURLに合わせる
3. **Prebuild を有効化する**（強く推奨）
   - Settings → Codespaces → Set up prebuild
   - `onCreateCommand`（= `npm install`）が事前実行された状態で配布される
   - 起動が数分 → 数十秒になり、オンボ時間が大幅に短縮される

## 4. 事前検証チェックリスト（必須）

**この構成は Codespaces 上での実地検証がまだ済んでいません。**
本番前に必ず自分のアカウントで一度通してください。

- [ ] Code → Codespaces → Create でコンテナが生成される
      （← ここが落ちたら `devcontainer.json` の `image` を差し替える）
- [ ] ターミナルに `セットアップ完了` と Claude Code のバージョンが出る
- [ ] `echo $HOME` が想定通り（`/home/codespace` など）
- [ ] `claude` がフルパスなしで起動し、対話画面が出る
- [ ] `bash scripts/setup-key.sh && source ~/.bashrc` が通る
- [ ] 本物のキーで `npm run doctor` が**全項目 OK**（`API疎通 成功` を確認）
- [ ] `npm test` が「13 pass / 1 fail」
- [ ] `npm start` → ポート3000が転送され、ブラウザで開ける
- [ ] 演習1〜3を実際に通す（所要時間を実測する）

> `image` の tag が引けない場合は、`devcontainer.json` のコメントにある
> 代替イメージに差し替えてください。それ以外の指定は極力削ってあるため、
> 落ちるとすればほぼここです。

## 5. 当日の進行

1. リポジトリURLを共有
2. 「Code → Codespaces → Create を押してください。**fork は不要です**」
3. 起動を待つ間にキーを**画面またはチャットで提示**（後で消せる場所が望ましい）
4. `bash scripts/setup-key.sh && source ~/.bashrc` を貼ってもらう
5. `npm run doctor` で**全員の状態を揃えてから**本題に入る

### つまずきポイント

| 症状 | 原因 | 対処 |
|------|------|------|
| Codespace が作成できない | 無料枠切れ | 枠を確認してもらう。予備は運営PCの画面共有 |
| `command not found` | PATH 未反映 | `source ~/.bashrc` → `npx claude` |
| HTTP 401 | 貼り付けミス | ステップ2をやり直す |
| HTTP 429 | 同時アクセス集中 | Workspace のレート上限を引き上げる |
| 起動が遅い | Prebuild 未設定 | 事前に Prebuild を有効化しておく |

---

## 6. 終了後（当日中に必ず実施）

**Workspace をアーカイブしてください。**

Workspace をアーカイブすると、その中の**全APIキーが即座に無効化**されます。
この操作は取り消せません。だからこそ、専用 Workspace を分けておくことが重要です。

- [ ] Workspace をアーカイブした
- [ ] 提示したチャット・スライドからキーを削除した
- [ ] Console の Usage で想定内の利用量だったか確認した

---

## 7. 次回に向けて

受講生ごとに使用量を分けたい、個別に失効させたい、という要求が出た場合は
**LLMプロキシ方式**への移行を検討してください。

本物のキーはプロキシ側にのみ置き、受講生には有効期限付きの使い捨てトークンを配ります。
Claude Code は `ANTHROPIC_BASE_URL` と `ANTHROPIC_AUTH_TOKEN` の
2つの環境変数で向き先と認証を差し替えられるため、教材側の変更はほぼ不要です
（`setup-key.sh` に1行足すだけで済みます）。

- 受講生ごとの使用量が可視化できる
- 個別にレート制限をかけられる
- トークンに TTL を設定し、終了時刻に自動失効させられる

引き換えにプロキシを1つ運用する手間が発生します。
今回の規模で不要なら、Workspace のキルスイッチで十分です。

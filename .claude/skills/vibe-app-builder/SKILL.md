# バイブコーディング実装ワークフロー

決まったアイデアの仕様をもとに、見た目の好みを短く聞いてから、その場で動く1枚のHTML/CSS/JSツールを実装する。「地味で驚きがない」という失敗を避け、短時間でも「おっ」と思える見た目に仕上げることを目的とする。

## 全体の流れ

```
work-idea-hearingスキルからの引き継ぎ（選ばれたアイデア＋簡易仕様）
    ↓
Step 1: 仕様の確認
    - 入力項目・出力・画面イメージをおさらい（未確定なら軽く確認）
    ↓
Step 2: 見た目ヒアリング（2〜3問・1分程度）
    - 色や雰囲気の好み
    - 欲しい「わくわく感」の要素
    ↓
Step 3: 方針を一言で共有
    - 「こんな雰囲気で、こういう動きをつけますね」と伝えてから実装に入る
    ↓
Step 4: 実装
    - references/wow-factor-patterns.md を参考に、時間内でできる「ちょっとした驚き」を1〜2個入れる
    - 1枚のHTMLファイル（インラインCSS/JS）で完結させる
    ↓
Step 5: 動作確認・お披露目準備
    - 参加者に python3 preview.py を実行してもらい、ブラウザで動かして見せる
```

## 使い方

work-idea-hearingスキルでアイデアと簡易仕様が決まった直後に、続けてこのスキルを使う。呼び出し例:
- 「これを実際に作って」「作ろう」
- 「さっき決めたアイデアを実装して」

## Step 1: 仕様の確認

work-idea-hearingスキルから引き継いだ「何を作るか・入力・出力・画面イメージ」を1〜2行でおさらいする。まだ曖昧な部分があれば、ここで1つだけ確認する（時間をかけすぎない）。

## Step 2: 見た目ヒアリング

進行の原則:
- 2〜3問だけ、1分程度でテンポよく聞く。デザインの深掘りに時間をかけない
- 専門用語（配色理論、UIコンポーネント等）は使わない
- 参加者が「特にこだわりない」「おまかせで」と言ったら、無理に聞き出さず、references/design-hearing-guide.md のおすすめパターンから1つ選んで進めてよい

聞くこと（`references/design-hearing-guide.md` に質問例と選択肢の例あり）:
1. 色・雰囲気の好み（例: きちんとした感じ／ポップで楽しい感じ／シックで落ち着いた感じ）
2. 欲しい「わくわく感」の要素（例: ボタンを押した時に何か動いてほしい、絵文字を使いたい、達成感のある演出がほしい）
3. （任意）好きな色、参考にしたいアプリやサービスの雰囲気

## Step 3: 方針の共有

ヒアリング結果をもとに、「〇〇な雰囲気で、△△という動きをつけて作りますね」と1文で伝えてから実装に入る。長い説明はしない。

## Step 4: 実装

**技術的な制約（work-idea-hearingスキルから引き継ぐ）**: 成果物は1枚のHTMLファイル（＋インラインCSS/JS）で完結する静的なツールにする。サーバー・データベース・外部API呼び出しは使わない。

**保存先は必ず `apps/` ディレクトリ**（例: `apps/nippou-generator.html`）。ここ以外に置くと、次のStep 5のプレビューに出てこない。ファイル名は内容がわかる英数字にする。

実装の指針:
- `references/wow-factor-patterns.md` を読み、時間内で実現できる「ちょっとした驚き」のパターンを1〜2個選んで組み込む（入れすぎない。詰め込みすぎると時間内に終わらない）
- 見た目だけでなく、Step2で確認した「本来の機能」がきちんと動くことを最優先にする。見た目は機能の上に乗せる仕上げ
- 迷ったら「地味すぎるより少しやりすぎるくらい」を意識する。装飾ゼロの入力フォーム＋出力欄だけ、という構成は避ける

## Step 5: 動作確認・お披露目準備

**重要**: この環境（GitHub Codespaces）はコンテナの中で動いているため、HTMLファイルを開く操作では参加者のブラウザに表示できない。必ず下記の手順を案内すること。

参加者にこう伝える:

> できました。ブラウザで見てみましょう。
> **新しいターミナルを開いて**（ターミナル右上の `+` アイコン）、次を貼り付けて Enter してください。
>
> ```bash
> python3 preview.py
> ```
>
> 画面の右下に通知が出るので「**ブラウザーで開く**」を押してください。

補足:
- `python` や `pip` はこの環境に存在しない。**必ず `python3`** と書くこと
- Claudeを動かしているターミナルはそのままにしてもらう（別タブで実行してもらう）
- 通知が消えてしまった場合は、画面下の「ポート」タブ → `3000` の地球儀アイコンから開ける
- 参加者から「うまく表示されない」と言われたら、まず `apps/` にファイルが保存されているかを確認する

表示できたら参加者と一緒に一通り操作してみて、明らかな不具合があれば直す。修正後はブラウザを再読み込みすれば反映される（`preview.py` は起動したままでよい）。次の「見せあいっこタイム」にそのまま使える状態にする。

## ディレクトリ構造

```
.claude/skills/vibe-app-builder/
├── SKILL.md                        # このファイル
└── references/
    ├── design-hearing-guide.md     # 見た目ヒアリングの質問例とパターン集
    └── wow-factor-patterns.md      # 短時間で実装できる「驚き」の実装パターン集
```

## 注意事項

- 見た目ヒアリングは短く。全体の実装時間（30〜45分程度）のうち、ヒアリングに使うのは1分程度に留める
- 「驚き」は入れすぎない。1〜2個で十分。本来の機能が埋もれるほど装飾に時間をかけない
- プログラミング未経験者向けなので、実装中にコードの詳細を延々と説明しない。動いた結果を見せることを優先する
- 成果物は必ず1枚のHTML（＋インラインCSS/JS）で完結させ、サーバーや外部API呼び出しを前提にしない
- **保存先は `apps/` ディレクトリ固定**。プレビュー（`preview.py`）が配信するのはこのフォルダのみ
